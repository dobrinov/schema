See your database schema.
And how it changes.

schema turns a structure.sql or schema.rb into an interactive ER diagram — and shows every migration as a visual diff straight from git. Focus on the tables that matter, hide the noise, share it anywhere.

Install

Homebrew macOS · Linux

brew install dobrinov/tap/schema

Later: brew upgrade schema, or just schema update.

Binaries macOS · Linux · Windows

Grab an archive from the latest release (Apple silicon and Intel, Linux x86_64 and arm64, Windows x86_64), unpack it and put schema on your PATH.

From source

git clone {{REPO_URL}} schema && cd schema
make install

Needs Rust with the wasm32-unknown-unknown target and wasm-pack.

Then run schema in a repository with a structure.sql or schema.rb. Everything git-related needs git on your PATH.

Built for reading real schemas

Rails apps grow to hundreds of tables. schema is designed to cut that down to the part you care about.

⎇

Git-aware diffs

Compare the working tree, staged changes, commits, branches or tags using familiar git ref syntax. Added tables glow green, drops are red and dashed, changed columns show int → bigint.

◎

Focus & filter

Focus on a few tables and their neighbours, include / exclude with globs, hide *_at columns everywhere or per table, collapse tables to keys only.

⌬

Five layouts, three edge styles

Layered (Sugiyama) in any direction, force-directed, grid, circular and radial. Orthogonal edges with rounded corners, own lanes and hops at crossings (curved and straight too), anchored to columns, with crow's-foot cardinality.

🐘

Postgres native

Parses pg_dump output: schemas, enums, partitions, identity & generated columns, partial indexes, views, materialized views, functions, triggers and comments. mysqldump output, SQLite schemas and Rails schema.rb files work too.

▣

WASM everywhere

The same Rust engine runs in the CLI, the browser viewer and a single-file embed. Export SVG, PNG or a self-contained HTML page that works offline.

✎

Design, then hand off

Sketch new tables and changes on top of your real schema, see them as a diff, and export a spec an agent turns into migrations. schema design check verifies the result.

✦

Made for AI agents

Skills let Claude Code (and other agents) open focused diagrams, review migrations, answer schema questions and generate HTML docs with embedded diagrams.

One command

Point it at a schema file. A local server starts and your browser opens. Run it again and the existing instance is reused; every repository gets its own port.

  • Live-reloads when the file, the index or HEAD changes
  • Pick any two versions from the file's history in the UI
  • Your display settings are remembered per file, named views live in .schema.json
# everyday use
schema                            # db/structure.sql, uncommitted changes
schema HEAD~1                     # what the last commit changed
schema main...feature             # what a PR would merge
schema --base-file old.sql        # no git? compare two files

# cut it down
schema --focus orders --depth 2 --columns keys
schema --exclude 'audit_*' --hide-columns created_at,updated_at
schema --layout radial --edges orthogonal --group-by schema

# share it
schema html main...HEAD --changes-only -o pr-diff.html
schema svg --focus users -o users.svg
schema diff main...HEAD            # Markdown summary for the PR
# in Claude Code (a chat prompt, not your terminal)
you › /schema-diff main...HEAD

Schema changes (merge-base → working tree)
  + task_watchers        new join table, 2 FKs
  ~ tasks.priority       integer → smallint
  − comments.edited_at   column dropped
  − index_comments_on_parent_id

Risks
  • comments.parent_id FK no longer has an index
  • dropping edited_at loses data – backfill first?

Skills for AI agents

Install the bundled skills in your app's repo and your coding agent knows how to use schema. Skills are slash commands you type in Claude Code; in a terminal you run schema itself (e.g. schema diff).

schema skills install          # ./.claude/skills
schema skills install --global # ~/.claude/skills
  • /schema-view — open a focused diagram for what you are working on
  • /schema-diff — review migrations and flag risky changes
  • /schema-inspect — answer schema questions without reading a 10k-line dump
  • /schema-embed — generate HTML docs with interactive diagrams
  • /schema-design — implement a design with migrations and verify it

Embed diagrams anywhere

One script tag gives any HTML page an interactive diagram — design docs, onboarding pages, generated reports. Everything renders client-side from SQL; nothing is uploaded.

See embedded examples →

<script src="schema.embed.js"></script>

<div data-schema style="height:480px"
     data-config='{"focus":["orders"],"columns":"keys"}'>
  <script type="application/sql">
    CREATE TABLE users  (id bigint PRIMARY KEY);
    CREATE TABLE orders (id bigint PRIMARY KEY,
      user_id bigint REFERENCES users(id));
  </script>
</div>

// or from JavaScript
Schema.mount(el, { sql, baseSql, config });
const svg = await Schema.render(sql, { layout: { algorithm: "force" } });
